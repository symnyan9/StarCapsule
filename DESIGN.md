# Studio visual system

The project is a desktop Operate surface: geometry and fields occupy the largest useful area; project actions, comparison links and view settings remain visible. A neutral graphite frame surrounds a light gray scientific canvas, with a restrained blue accent for active controls. Synthetic cases always carry a readable amber DEMO identifier.

Use the native system sans stack for functional controls. Numeric measurements use tabular figures; monospace is restricted to source identifiers and coordinates. Small labels remain at least 12 px. Inputs and buttons have explicit keyboard focus, disabled, hover and error states. Sidebars scroll independently; no card or control may force a horizontal canvas overflow.

The shell contains a compact top bar, a comparison-link bar, a narrow project/comment sidebar, and one or two equal-width views. Each view contains a case selector, editable display name, camera controls, the viewport, and its own collapsible scientific settings. Names and comments are inserted as text, never interpreted as markup.

There are no external fonts, CDN scripts, remote logos, marketing claims or decorative illustrations. Authored SVG icons share a 24-unit viewBox and 1.7-unit stroke. The surface is desktop-first; preserving usable narrow comparison canvases takes priority over inventing a mobile workflow.

Picked scalar values use a separate blue filled rectangle with white 18 px tabular numerals. Component identity and coordinates use secondary 12 px text. The readout overlays the upper-left canvas without changing its layout height; the empty state stays hidden until picking is enabled. Project/comparison controls share one header, and the case selector shares the camera toolbar. More, Camera, case details and A/B sync use native disclosure menus; touch targets remain at least 44 px. With one live view, A/B sync explains its scope and disables its checkboxes while retaining saved preferences. The HTML creator credit shares the active viewport's existing status row and reserves horizontal space there; it adds no bottom row or vertical padding. Fullscreen and re-rendered views retain one credit.

The Windows SIM exporter extends the same neutral graphite/blue system through native Tk/ttk controls. A compact header and source-path row lead to two functional columns: expandable/searchable wall and existing-postprocessing trees in native tabs on the left; exact field names, display ranges and optional X planes on the right. Existing postprocessing rows expose concrete names, mesh-capable type and source-scene scalar; group rows merely organize selectable objects. The active tab holds layer coloring and opacity without increasing the right column's height. Title and HTML location occupy a full-width row below them, with status and the primary export action in a fixed footer. Native file/save dialogs, extended tree selection, keyboard focus and disabled controls express workflow state. The form defaults to no selected boundaries, no sections and no symmetry reflection. Bounds status names the selection as its source and offers an explicit reset alongside editable X limits. Progress is indeterminate while the local native process runs; errors identify the required next action and keep the report/source intact.

Local template selection and its current display name share the existing compact header; the reset action stays beside the picker. This adds no form row or scroll requirement. The fixed footer displays “Designed by Symn” in a small, high-contrast Segoe UI caption beside result/task-folder actions. It is an authored credit label rather than a mutable field or template setting.
